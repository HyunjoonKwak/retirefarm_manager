# 브리핑 서버 적용·검증

이 변경은 API 키 방식의 AI SDK를 추가하지 않는다. 서버는 집계와 작업 큐만 관리하고 Mac의 로그인된 Codex가 초안을 작성한다. 수집 스케줄러와 별개이며 월요일 예약·텔레그램은 아직 등록하지 않는다.

## 적용 대상

- Prisma migration: `20260914030000_briefing_worker` (새 테이블 세 개, 기존 자료 수정·삭제 없음).
- `/reports`의 주간 브리핑 탭.
- 로그인 사용자용 `GET/POST /api/briefings`, `POST /api/briefings/worker-token`.
- 전용 bearer 인증 워커용 `POST /api/briefing-worker`.

서버 환경에 OpenAI 키나 Codex 로그인 파일을 추가하지 않는다. 워커 토큰은 로그인 사용자가 UI에서 발급하며 사용자 자신의 작업에만 접근한다. Mac의 설정은 별도 워커 안내를 따른다.

## 배포 시 확인 순서

1. 검증된 온라인 DB 백업을 먼저 생성한다. 운영 DB 파일의 단순 복사를 사용하지 않는다.
2. 테스트·빌드가 통과한 이미지에 새 migration을 포함해 기존 `migrate deploy` 시작 경로로 적용한다. 운영 `db push`는 사용하지 않는다.
3. readiness와 기존 시세 조회 확인 후 리포트 화면에서 주간 브리핑 탭을 연다. 미등록 워커 상태와 기존 월간·연간 탭을 확인한다.
4. 본인 워커 토큰을 발급해 Mac 비공개 파일에 저장하고 접근 권한을 제한한다. 앱이 생성한 토큰 원문을 로그나 Git에 보관하지 않는다.
5. 좁은 시세 조건으로 초안을 요청하고 Mac 워커를 한 번 실행한다. 워커에는 실제 구독 사용량이 발생한다. 완료 결과는 초안으로만 저장된다.
6. 수치·근거·미수집 설명·우선 행동을 사람이 확인한다. 연결 끊김·사용량 한도 상황을 확인한 후 향후 자동 예약 단계로 진행한다.

## 운영 상태 해석

| 상태 | 의미·조치 |
|---|---|
| PENDING | Mac이 아직 작업을 가져오지 않음. 최신 연결 시각과 Mac 가용성 확인 |
| RUNNING | lease를 가진 워커가 작성 중. 만료 후 다음 claim에서 자동 복구, 최대 세 번 |
| BLOCKED | 인증/사용량 한도 문제. 연결 문제 해결 후 UI에서 명시적 재시도 |
| FAILED | 형식·시간·CLI 실행 실패. 원인을 확인한 뒤 재시도 |
| SUCCEEDED | 검증된 JSON 초안을 저장함. 발행·발송 완료를 뜻하지 않음 |

동일 주간·동일 입력 해시는 기존 작업을 반환한다. 생성 중 입력이 달라지면 별도 작업으로 남는다. 실행 중 워커 토큰을 재발급/폐기하면 기존 워커는 더 이상 완료를 제출할 수 없다.

완료 응답이 유실된 경우 워커는 같은 결과만 제한적으로 재전달하며 AI를 다시 실행하지 않는다. 완료 요청은 멱등 처리한다. 전송 불확실 상태는 워커 로그와 앱 저장 여부를 대조한다.

## 되돌리기

이전 앱 이미지로 되돌려도 새 테이블은 그대로 둘 수 있다. 이미 생성된 보고서를 삭제하는 down migration은 제공하지 않는다. 코드 롤백과 DB 전체 복원은 별개의 조치이며, 백업 이후의 시세를 잃는 전체 복원을 자동 수행하지 않는다.

## 알려진 한계

원자료 수집 완전성·과거 복구는 별도 작업이다. 원자료 가중평균의 전주·직전 네 주 비교와 수집 로그 확인은 [후속 비교 기능](reviews/2026-09-14-briefing-comparison.md)에서 제공한다. 기존 Work의 공개 일평균 시계열 이전은 별도 작업이다. API 접근 제어나 모델 출력 형식 검증만으로 서술 내용의 사실성이 보장되지는 않는다. 전체 Work 보고서 대체 선언은 출처 수집·과거 보고서 이전·병행 검증 후에 한다.
