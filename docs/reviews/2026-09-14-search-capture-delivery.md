# 검색 화면 후보 수집 연결

## 실제 확인한 검색 방식

2026-09-14 Chrome에서 대추방울토마토 2kg를 검색했다. 가격비교(`/search/all`) 상단에는 광고 이동 주소가 사용됐다. 네이버플러스(`/ns/search`)에는 추천순·판매 많은순·리뷰 많은순 등의 정렬과 일반 상품 목록이 있었다. 실제 판매처별 전체 판매량이나 검색량이 공개됐다고 해석하지 않는다.

일반 카드에는 `basic_product_card_information_<번호>` 영역, 상품 제목, 판매처 링크, 리뷰 표시가 있었다. 상품 링크는 `/main/products/<번호>`, 판매처 링크는 `/inflow/outlink/url?url=...`인 경우가 있었다. 같은 카드의 공개 판매처 링크와 상품 번호로 주소를 제안할 수 있으나 실제 페이지에서 대조해야 한다. 광고의 불투명한 이동 주소를 실제 상품 주소로 저장하지 않는다.

직접 DOM 평가 도구의 시간 초과가 반복됐고, 별도 검색 탭에서 **보안 확인을 완료해 주세요** 화면과 캡차 입력 폼이 나타났다. 사용자에게 해당 탭의 보안 확인을 직접 완료해 달라고 요청했다. 접근 제한 우회나 자동 캡차 처리는 하지 않았다. 이 상태에서는 무인 반복 방문을 검증 완료로 볼 수 없다.

## 이번 변경

- 수집 확장 1.1.0: 상품 가격 수집을 유지하면서 네이버플러스 검색 카드 최대 20개를 파일로 내보내는 경로 추가. 추가 권한·서버 통신·백그라운드 방문 없음.
- `retirefarm-visible-search-v1` 파일에는 검색 출처·검색어·정렬·수집 시각·상품 후보가 포함된다. 개인화·배송지·필터는 미확인이다. 출처 URL은 검색어·정렬·페이지 외 추적 파라미터 등을 제거하며 원래 필터 상태 전체를 재현한다고 보장하지 않는다.
- 직접 주소 / 조합 주소 / 실제 주소 미확인을 구분한다. 조합은 같은 카드에 판매처와 단일 상품 번호가 함께 있을 때만 가능하다.
- 광고가 확인되면 AD, 그 외도 UNKNOWN으로 내보낸다. 광고 배지 부재만으로 비광고라고 단정하지 않는다. 리뷰 수는 집계 기준 UNKNOWN, 구매 표기는 설명용으로 보존한다.
- 앱 가져오기 미리보기에서 후보 선택·주소 대조·광고 및 품목 확인을 거친 후 저장한다. 처음에는 아무 후보도 선택하지 않는다. 캡처에서 확인된 광고는 비광고로 변경할 수 없다. 편집하면 확인 체크를 해제한다.
- 최근 24시간 이내 파일만 미리보기와 저장에 사용한다. 출처 검색어 불일치·위치 중복·잘못된 주소·과대 파일을 거부한다. 원래 수집 시각을 보존한다.
- 검색 근거에 출처·정렬·검색 환경·수집 방법을 함께 저장하고 후보 근거 화면에서 표시한다. 기존 수동 입력의 저장 해시와 재시도 동작을 유지한다. 같은 검색어를 다른 환경에서 반복해도 노출 검색어 수를 부풀리지 않는다.

상품 가격 파일과 검색 후보 파일은 별도 형식이다. 검색 후보 파일은 **경쟁 판매처 추천 후보 → 검색 근거 추가 → 검색 후보 JSON 파일 가져오기**에서 사용한다. 기존 설치는 ZIP을 새로 받아 소스 폴더를 교체한 뒤 Chrome 확장 관리 화면에서 새로고침한다.

## 검증 범위와 남은 단계

실제 검색 화면의 카드 표시와 정렬은 관측했지만 설치된 확장에서 추출 → 파일 저장 → 앱 가져오기 전체 흐름은 아직 실자료로 통과하지 않았다. 추출기 테스트는 관측한 구조를 바탕으로 만든 통제된 DOM 표본이며 사이트 전체의 동작 증명이 아니다. 지원 구조 미인식·보안 확인은 실패로 반환하고 빈 수집 성공으로 처리하지 않는다.

후속 순서:

1. 사용자가 보안 확인을 완료한 브라우저에서 확장 1.1.0을 설치·갱신하고 실제 검색 결과 3개 검색어로 추출 값·제안 URL·광고 표시를 대조한다.
2. 불확실한 카드 구조를 보완하고 같은 옵션의 3–5개 판매처에서 반복 가격 확인을 한다.
3. 제한·로그인 필요·화면 변경을 사용자에게 표시하는 Mac 작업 큐와 재개 상태를 연결한다. 실행 시각·최종 성공·실패 원인·미실행을 구분한다.
4. 접근 안정성을 확인한 뒤 주간 실행을 활성화하고 추천 변화와 고정 비교 가격을 보고서에 통합한다. 현재는 주간 검색 예약을 구현·활성화했다고 표시하지 않는다.

Claude는 검색 출처 계약·기존 저장 호환성 및 추출기 테스트·보완을, Codex는 실사이트 확인·확장 팝업·앱 미리보기·통합·배포를 담당했다. 페이지마다 AI를 호출하지 않는 규칙 기반 수집·평가를 유지한다.
