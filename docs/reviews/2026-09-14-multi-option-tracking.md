# 판매처별 복수 옵션 추적

## 구현 범위

판매처 30곳까지, 각 판매처 활성 옵션 10개까지 추적한다. 화면과 주간 보고서에서 활성 점포 수와 옵션 수를 분리한다. 같은 판매처의 다른 상품/중량/색상 옵션을 등록할 수 있으며, 후보와 기존 패널의 '다른 옵션' 버튼은 판매처/주소만 채우고 옵션·중량·품종 등은 새로 확인하게 한다.

동일 상품 URL + 앞뒤 공백을 제거한 옵션명 + 포장 중량은 동일 옵션으로 취급한다. 품종명·색상·가공 등 비교 조건만 바꿔 중복 등록하지 못한다. 기존 옵션의 조건 정정은 보관 후 재등록하며 과거 관측을 새 조건으로 소급 변경하지 않는다. 옵션 하나를 보관해도 같은 점포의 다른 옵션은 유지된다.

## 통계 및 보고서

같은 비교 그룹의 한 점포에서 유효한 옵션이 여러 개면 최신 유효 관측을 가진 옵션 한 건을 선택한다. 최저가 선택이나 옵션 개수 가중치를 사용하지 않는다. 같은 시각은 항목 ID로 결정한다. 선택한 옵션의 이력만 전주 비교에 사용한다. 품절/미확인 옵션 때문에 같은 점포의 유효한 다른 옵션이 가려지지 않는다.

품종명·색상·혼합·가공·크기 기준에 대한 이전 검증 조건 및 서로 다른 3곳 이상이라는 기준은 유지한다. 보고서에는 점포/옵션 수와 그룹당 한 표본 정책을 함께 제공한다.

## DB 호환

activeOptionKey를 추가하고 기존 점포 단위 유일 인덱스를 옵션 단위 유일 인덱스로 교체한다. 기존 활성 옵션은 legacy:<id> 키로 보존하며 서비스가 동일 옵션 여부를 계산해 중복을 막는다. 보관 옵션은 activeOptionKey가 null이다. activeStoreKey는 기존 점포 표식으로 유지하되 더 이상 유일하지 않다. 기존 패널 ID와 관측은 유지한다.

복수 옵션 저장 후 이전 버전으로 단순히 되돌리면 이전의 점포 수 계산·등록 로직은 복수 옵션을 정확히 처리하지 못한다. 문제 발생 시 새 데이터를 지우거나 이전 유일 인덱스를 강제 복구하지 말고 수정 버전을 배포한다. DB 백업은 데이터 복구가 실제 필요한 경우에만 사용한다.

## 실제 확인 예정 자료

구성포냥냥파머즈 상품 12280882374의 루체(주황) 2kg은 기존 16,900원/기본 무료배송으로 기록되어 있다. 2026-09-14 18:52 KST 같은 상품의 엠버(노랑) 2kg을 수량1로 선택했을 때 총액17,900원과 기본 무료배송을 확인했다. 제주/도서지역 추가5,000원은 공통 배송 표기다. 배포 후 두 번째 옵션으로 기록하고 점포1곳/옵션2개 표시를 확인한다.

품종명과 판매명 동등성·무가공 여부·크기 수치 기준은 여전히 미확인이므로 이 자료를 대표 가격으로 승격하지 않는다. 루체의 주황/레드 충돌 메모도 보존한다.

## 후속 범위

현재 옵션 식별은 직접 확인한 URL/옵션명/중량이다. 판매자가 옵션명을 바꾸면 자동으로 같은 옵션이라고 추정하지 않는다. 판매처의 안정적인 옵션 식별자를 확보하는 수집 방식과 명칭 변경 검토 흐름은 후속 작업이다. 주간 예약 브라우저 수집과 보안 확인 후 재개 자동화도 아직 구현되지 않았다.

## 검증

전체 70개 테스트 파일, 852개 테스트 통과. UI/보고서 관련 30개 테스트 통과. TypeScript 검사와 변경 파일 lint 통과. 임시 SQLite 마이그레이션에서 기존 활성/보관 항목과 관측 보존 및 Prisma 스키마 일치를 확인했다. 실제 운영 DB는 배포 후 추가 검증한다.
