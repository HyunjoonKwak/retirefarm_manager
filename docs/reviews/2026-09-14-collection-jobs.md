# 검색 수집 작업 관리

## 이번 구현 범위

실제 검색 JSON을 앱에 가져와 검토 후보를 저장하는 흐름에 검색어별 진행 기록을 연결한다. 브라우저 방문은 사용자가 수행하며 확장 실행도 버튼 방식이다. 자동 실행 워커나 주간 스케줄러는 이번 기능에 포함되지 않는다.

한국 시간 월요일을 기준으로 사용자·주차·정규화 검색어마다 작업을 하나 만든다. 한 번에 검색어 1–3개, 진행 중 작업 최대 9개, 최근 24시간 생성 최대 30개다. 같은 주의 같은 검색어를 다시 준비해도 중복 생성하지 않는다. 완료·취소한 작업도 같은 주에는 별도 재생성하지 않는다. 추가 관측은 작업 연결 없이 기존 가져오기에서 저장할 수 있다.

| 상태 | 의미 | 다음 동작 |
| --- | --- | --- |
| 대기 | 이번 주 수집할 검색어 등록 | 사용자가 시작 또는 취소 |
| 수집·검토 중 | 사용자가 시작·재개를 표시 | JSON 검토 후 저장, 중단 기록 또는 취소 |
| 확인 후 재개 필요 | 보안 확인·로그인·화면 변경·연결 오류·브라우저 사용 불가 | 사용자가 확인 후 재개하거나 취소 |
| 검토한 근거 저장 완료 | 선택한 검색 근거가 저장됨 | 기록 열람 |
| 취소 | 이번 주 해당 작업 중지 | 기록 열람 |

한 사용자에게 수집·검토 중 작업은 하나만 허용한다. 이 상태는 브라우저 프로세스가 실제 실행 중이라는 감지 결과가 아니라 사용자의 시작 신호다. 새로고침이나 다른 기기에서 바뀐 작업 상태는 version 검사로 충돌을 막는다. 자동으로 캡차를 해결하거나 탭을 늘리거나 재시도하지 않는다.

## 사용 흐름

1. 리포트 → 경쟁점 조사 → 경쟁 판매처 추천 후보 → 검색 수집 작업 관리를 연다.
2. 검색어를 한 줄에 하나씩 입력하고 이번 주 작업 준비를 누른다.
3. 작업을 시작한다. 검색 열기는 현재 탭에서 이동하므로 수집 후 뒤로 돌아온다. 기존 네이버 탭을 쓰려면 그 탭에서 같은 검색어를 입력해 사용한다.
4. 보안 확인 등으로 진행하지 못하면 중단 사유를 기록한다. 확인을 마친 뒤 재개하고 새로 수집한다.
5. 돌아온 앱에서 이 작업에 파일 연결을 선택하고 검색 후보 JSON을 가져온다. 시작·재개 후 관측한 같은 검색어 파일만 연결할 수 있다.
6. 실제 상품 주소·광고·품목을 검토하고 선택한 근거를 저장한다. 후보 저장과 작업 완료를 하나의 DB 트랜잭션으로 처리한다. 실패하면 둘 다 반영하지 않는다.

가져온 전체 20개 중 1개를 검토해 저장했다면 완료 기록도 선택한 근거의 저장을 의미한다. 검색 결과 전체 처리, 고정 패널 편입, 옵션 가격 관측 완료를 뜻하지 않는다. 기존 파일 가져오기·수동 입력은 작업 연결 없이도 그대로 사용할 수 있다.

## 호환성과 데이터 보호

기존 검색 근거의 내용 해시는 바꾸지 않는다. 작업 연결 정보는 import 요청에 선택 항목으로 추가하고 두 항목(id와 version)을 함께 요구한다. 같은 작업의 같은 자료 재전송은 중복 저장하지 않는다. 다른 사용자 작업, 중단·취소 상태, 오래된 version, 다른 검색어, 시작 전 관측, 확장 출처가 없는 자료는 거부한다.

목록과 마지막 완료 시각은 현재 사용자 범위로 조회한다. 다른 사용자의 성공 시각을 내 수집 성공으로 표시하지 않는다. 활성 작업은 최근 기록 페이지 밖으로 밀려나도 조회에 포함한다.

## 다음 단계

- 확장 1.1.1로 선택 정렬이 담긴 새 JSON을 실제 검증한다.
- 대표 검색어 3개와 동일 옵션 3–5개 판매처로 검증 범위를 늘린다.
- 별도 Mac 브라우저 워커의 작업 인수·생존 확인·중단 알림을 구현한다. 현재 사용자 시작 API를 곧바로 무인 워커 인증에 쓰지 않는다.
- 반복 수집이 안정된 뒤 주간 예약·추천 변화·고정 비교 가격을 보고서에 연결한다.

Claude는 DB·API·작업 전환·저장 일괄 처리와 통합 테스트를, Codex는 작업 화면·파일 연결·UI 테스트·리뷰·배포를 담당한다.

## 배포 전 검증

- 전체 Vitest 70개 파일, 813개 테스트 통과.
- TypeScript 및 변경 코드 lint 검사 통과.
- 실제 SQLite 통합 테스트로 사용자 격리, KST 주차, 중복 생성, 한 사용자당 동시 실행 1개, 중단·재개·취소, 오래된 version 거부, 저장과 완료의 일괄 반영, 실패 시 전체 롤백 확인.
- 완료한 같은 자료의 48시간 뒤 재전송은 기존 성공을 반환한다. 기존 입력 검증과 동일하게 관측 후 30일 이내라는 상한은 유지한다.
- 이전 저장 자료 일부만 다시 연결해 새 근거가 0개인 경우는 오류로 처리하고 빈 저장 기록도 롤백한다.
- UI 테스트는 작업을 펼치기 전 네트워크 요청 없음, 검색어 입력 검증, 시작 후 작업 연결, 보안 확인 중단·재개, 버전 충돌 안내, 다른 검색어·작업 시작 전 파일 거부를 포함한다.
- Claude의 서버 구현 및 보완 작업 2건 모두 완료 보고를 수신하고 작업 터미널을 정리했다.
