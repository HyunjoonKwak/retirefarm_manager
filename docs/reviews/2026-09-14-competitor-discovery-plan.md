# 경쟁 판매처 자동 발굴·선정 계획

작성: 2026-09-14. 상태: [후보 저장·근거 기반 자동 추천 1차 구현](2026-09-14-competitor-discovery-delivery.md)을 진행했다. 자동 검색 화면 방문·예약 실행은 아직 구현하지 않았다.

후속: [검색 수집 확장과 앱 미리보기 연결](2026-09-14-search-capture-delivery.md). 실제 반복 접속에서 네이버 보안 확인이 발생해 무인 운영 활성화와 실자료 전체 흐름 검증은 보류했다.

## 현재 동작

리포트 → 경쟁점 조사에서 브라우저 검색 링크로 상품을 찾은 뒤 사용자가 판매처·상품 URL·선택 옵션·품종·중량·크기 기준을 입력한다. 고정 비교 대상은 최대 30개 판매처이며 판매처당 상품·옵션 하나를 추적한다. 수집 확장은 현재 열어 둔 상품의 가격 영역을 가져오는 도구로, 검색 결과 탐색이나 판매처 선정을 수행하지 않는다. 스마트스토어와 브랜드스토어의 동일 판매자 여부는 아직 자동 통합하지 않는다.

## 목표와 지표의 의미

매주 후보를 스스로 발견하고 선정 근거를 제시하며, 검증된 고정 상품의 가격 추세와 함께 주간 보고서에 반영한다. 네이버는 검색 관련성·인기도·신뢰도 등을 노출에 반영한다고 설명한다. 따라서 검색 순위를 판매량 순위나 판매처 검색량으로 바꾸어 표시하지 않는다.

근거: [네이버 쇼핑 노출 기준](https://help.pay.naver.com/faq/content.help?faqId=10863), 확인일 2026-09-14.

| 지표 | 수집·가공 원칙 | 표시 이름 |
| --- | --- | --- |
| 검색 결과 위치 | 검색어·정렬·관측 시각·검색 환경·광고 여부를 함께 저장. 여러 검색어의 반복 노출을 평가 | 관측 검색 노출 상위 |
| 공개 구매 수 | 화면에 표시된 기간·단위·반올림 표현을 보존. 기간이 다르면 직접 비교하지 않음 | 공개 구매 지표 상위 |
| 리뷰 증가 | 동일 상품의 누적 리뷰 수를 같은 기간에 관측한 경우에만 차이 계산. 감소·집계 변경은 검토 대상으로 처리 | 최근 리뷰 증가 |
| 품목 적합성 | 품종·중량·크기 기준·산지·가공 여부·재고·배송 조건 확인 | 비교 조건 일치 |

경쟁 판매처의 실제 전체 판매량·검색량을 확보했다고 주장하지 않는다. 최근 6개월처럼 이동 기간의 리뷰 수 차이는 신규 리뷰 수로 해석하지 않는다. 미확인 값은 0점이나 판매 부진으로 처리하지 않고 자료 부족으로 표시한다. 검색 결과 가격은 선택 옵션의 검증된 가격으로 저장하지 않는다.

## 운영 기본안

- 매주 검색어 3개 × 첫 20개 결과, 최대 60개 후보를 탐색하는 작은 시험부터 시작한다. 초기 검색어는 대추방울토마토 2kg·3kg 및 재배 품목의 대표 검색어로 구성하고 설정에서 변경한다.
- URL 정규화와 상품 중복 제거 후 판매처별로 집계한다. 같은 상품이 여러 검색어에 등장해도 구매 수를 중복 합산하지 않는다. 호스트가 다른 동일 판매자는 공개 판매자 근거가 확인될 때만 연결한다.
- 품목 불일치·가공품은 제외하고 광고는 별도 분류한다. 광고 여부 미확인 자료로 비광고 순위를 만들지 않는다. 산지는 원문과 검증 상태를 보존한다.
- 상위 추천 후보 10곳을 별도 목록에 둔다. 기존 최대 30곳의 고정 비교 목록은 유지하고 추천 후보를 자동으로 덮어쓰지 않는다. 각 후보에 선정 사유·자료 시각·부족한 조건을 표시한다.
- 초기에는 후보 추천까지 자동화하고 고정 비교 편입 때 정확한 옵션을 확인한다. 반복 검증 이후 조건이 확정된 후보의 자동 편입 정책을 추가한다. 제외·보관한 판매처의 재추천 억제와 사용자 고정을 우선한다.
- 고정 목록 교체 시 이력을 남기고, 같은 판매처·옵션을 유지한 가격 변화와 표본 교체 효과를 보고서에서 구분한다. 서로 다른 크기·품종의 가격을 하나의 평균으로 합치지 않는다.

## 구현 순서와 완료 기준

1. **후보 저장·평가·화면**: 사용자별 DiscoveryRun, Candidate, Evidence, SelectionDecision 모델과 추천/고정/제외 화면. 원문 근거, 발견·최종 확인 시각, 정규화 URL, 지표 기간, 정책 버전을 보존한다. 원시 페이지 전체와 개인정보는 저장하지 않는다. 후보 입력을 가격 관측과 분리한다.
2. **검색 화면 수집**: 현재 상품 전용 확장과 별도의 검색 결과 수집 기능을 만든다. 실제 공개 화면 3개 검색어에서 URL·위치·광고 식별을 대조하고 구조 변경·빈 결과·접근 제한을 정상 결과와 구분한다. 수집 자료는 형식·크기·출처를 검증한다.
3. **선정 규칙**: 비교 조건 적합성을 필수 조건으로 두고 검색 노출·구매 지표·리뷰 증가를 별도 순위로 제공한다. 혼합 점수의 가중치는 실자료 확보 후 확정하고 정책 버전을 붙인다. 자료 충족률과 근거를 함께 표시하며, 누락 지표가 많은 후보가 유리해지지 않게 한다. 중복·기간 불일치·광고·미확인 조건에 대한 테스트를 추가한다.
4. **옵션 검증과 가격 수집 연결**: 추천 후보 중 3–5개 판매처에서 동일 옵션·중량·배송비를 직접 대조한다. 현재 상품 수집 도구와 연결하고 검증되지 않은 옵션은 통계에서 제외한다.
5. **주간 실행**: Mac 브라우저 워커 가용성을 확인한 뒤 발견 → 중복 제거 → 평가 → 옵션 확인 → 추천 저장 작업을 예약한다. 사용자·주차·검색 설정 기준 중복 실행 방지, 단계별 재개, 제한된 재시도, 실패 이유와 마지막 성공 시각을 구현한다. 접근 제한은 중단·검토 대상으로 처리한다. 최소 2회 주간 시험 후 자동 운영으로 전환한다.
6. **주간 보고서**: 새롭게 등장한 판매처, 노출 변화, 리뷰 증가, 품절·배송 조건 변화, 선정·제외 이유, 고정 비교 가격 변화를 함께 제공한다. 누락된 수집을 최신 데이터로 표시하지 않는다. 텔레그램 발송은 토큰 연결 후 별도 활성화한다.

완료 판단은 후보 자동 생성과 저장, 근거 추적, 사용자 격리, 재실행 중복 방지, 옵션 가격 정확성, 실패 표시, 실제 예약 반복 성공으로 한다. 후보 화면만 구현하고 자동 운영 완료로 보고하지 않는다.

## 역할·비용 관리

다음 구현 시 Claude에는 후보 평가 규칙·단위 테스트, Codex에는 저장·화면·브라우저 통합·배포를 독립적으로 분담한다. 파일 소유 범위를 먼저 나누고 결과를 상호 검토한다. 정규화·중복 제거·순위 계산은 규칙 기반으로 실행하며 페이지마다 AI를 호출하지 않는다. AI는 모호한 품종 분류와 최종 보고서 설명에 한정하고, 이전 결과를 재사용한다.

기본안으로 개발 준비를 진행할 수 있다. 실제 운영 전 확정할 설정은 재배 품목과 대표 검색어, 우선 비교 중량·크기·산지, 실행 시간, 자동 편입 허용 범위다. 지금은 자동 추천과 고정 목록 유지로 설정한다.
