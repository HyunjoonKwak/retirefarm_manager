## 결론과 정정

네이버 쇼핑검색 API는 2026-07-31 종료됐다. 남아 있는 레퍼런스 문서를 근거로 키 연결을 안내했던 판단을 정정한다. 새 키 준비는 필요 없다. [공식 종료 공지](https://developers.naver.com/notice/article/32564)

공개 브라우저 화면에서 검색 후보를 찾고 상품 옵션별 가격을 확인하는 경로는 실제로 동작했다. 서버 HTTP 수집, 일반 Playwright 워커의 반복 실행, 스마트스토어 전체 및 30개 판매처의 안정성은 아직 검증하지 않았다.

## Claude와 분담한 코드 검토

Claude는 `store_manager` 스크레이퍼·확장과 이 프로젝트의 관측 계약을 읽기 전용으로 검토했고, Codex는 공식 공지와 실제 브라우저를 검증했다.

- `store_manager/chrome-extension/src/content.js`의 화면 추출 구조를 참고할 수 있다. 해시 CSS 클래스와 선택 옵션을 반영하지 않는 가격 추출은 그대로 재사용하지 않는다.
- 기존 Playwright/Puppeteer 스크레이퍼는 주로 제목·이미지 등 메타데이터를 추출한다. 옵션 가격·배송비 수집기를 이미 보유한 것으로 간주하지 않는다.
- 기존 `record` 액션은 가격·배송비·재고·시각·메모를 받으므로 사람이 확인하는 보조 입력은 재사용 가능하다. 전체 HTML은 기존 8KB 요청 한도에 넣지 않는다.
- 현재 상품 URL 검증은 `smartstore.naver.com`만 허용한다. 실제 발견된 `brand.naver.com` 상품 지원이 필요하다. 호스트·판매자·상품 ID를 보존하고, 두 호스트의 동일 판매자 여부는 별도 확인한다.
- 현재 통계 그룹 키는 품목·품종군·품질군·중량이며 크기가 없다. 소과와 중과가 섞일 수 있으므로 수집 확대 전에 보완한다.

## 단계별 구현

### 1. 종료된 검색 경로와 비교 조건 정리

- UI의 키 등록 안내를 종료 안내 및 브라우저 후보 찾기 동선으로 교체한다. 서버 검색 액션도 명시적 종료 응답으로 막는다. 수동 관측과 기존 이력은 보존한다.
- 브랜드스토어 URL을 허용하되 HTTPS, 정확한 호스트·상품 경로 검증과 쿼리 제거를 유지한다.
- 크기 등급 원문, 정규화 크기, 판매자 기준의 지름/개수 범위를 보존한다. 판매처마다 다른 '로얄과' 표현을 자동으로 '중과'와 동일시하지 않는다.
- 크기 미확인 기존 자료는 '미확인'으로 유지하고 크기 확인 비교군에 섞지 않는다. 통계는 품종·크기·품질·포장 중량·배송 조건이 일치하는 서로 다른 3개 점포부터 제공한다.

### 2. 사람이 확인하는 브라우저 추출 도구

최소 버전은 상품 페이지에서 옵션을 선택한 뒤 화면 텍스트를 붙여넣으면 기록 폼을 채우는 방식이다. 이어서 확장의 '현재 상품 가격 가져오기' 버튼으로 복사 단계를 줄인다. [Chrome activeTab](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab)을 사용하는 명시적 클릭 방식이 후보이다.

- URL, 판매자, 선택 옵션 전체 경로, 중량, 수량 1의 상품가, 배송비, 재고, 관측 시각, 해당 값의 화면 근거를 추출한다.
- 검색 대표가·취소선 정상가·선택 옵션가·조건부 쿠폰가·포인트를 구분한다. 쿠폰·포인트는 기본 비교가격에서 차감하지 않는다.
- 조건부 무료·지역 추가 배송·복수 가격·옵션 미선택은 미확인으로 남긴다. 품절 문구가 없다는 이유만으로 판매 중으로 확정하지 않는다.
- 저장 전 기존 고정 옵션과 일치 여부를 검토한다. 옵션 불일치는 같은 패널에 저장할 수 없고 옵션 재선택 또는 새 비교 대상 검토로 연결한다.
- 최초 연결은 추출 JSON/텍스트를 앱에서 검토·저장하는 방식으로 인증 경계를 단순하게 유지한다. 확장에서 서버로 직접 전송하는 기능은 별도 인증·권한 설계 후 추가한다.

### 3. 고정 상품의 주간 반복 확인

3–5개 판매처에서 며칠간 수동 값과 추출 값을 대조한 뒤, 고정 URL과 고정 옵션을 Mac 브라우저 워커가 순차 확인하는 시험을 한다. 사이트 접근 조건과 실제 제한을 먼저 확인하고 허용되는 범위에서만 확대한다. 공개 화면 1회 성공은 무인 수집 가능성이나 사용 허용 범위를 보장하지 않는다.

- 별도 브라우저 프로필을 사용하는 화면 렌더링 방식이 후보이다. [Playwright persistent context](https://playwright.dev/docs/api/class-browsertype#browser-type-launch-persistent-context)
- NAS는 저장·통계·예약 상태를, Mac은 브라우저 실행을 담당한다. 기본 Chrome 인증 파일을 NAS로 복사하지 않는다.
- 한 번에 한 페이지, 실행 시간·재시도 상한, 취소, 중복 저장 방지를 적용한다. 로그인 요구·접근 제한·CAPTCHA·레이아웃 변경은 중단 후 확인 필요 상태로 보낸다.
- 월요일 10시 예약에서 Mac 꺼짐·옵션 품절·수집 실패를 별도로 보고한다. 실패를 0원이나 이전 가격의 새 관측으로 바꾸지 않는다.
- 전체 검색 결과는 판매처 발견에 사용하고, 주간 비교는 고정된 최대 30개 판매처를 대상으로 한다. 검색 순서를 비광고 시장 순위로 표시하지 않는다.

## 검증과 운영 기준

대표가/옵션가 혼재, 조건부 쿠폰, 배송비 미확인, 선택 옵션 불일치, 동일 이름의 서로 다른 크기 기준, 옵션 품절, 브랜드 URL, 중복 저장을 테스트한다. 실제 페이지 몇 곳의 수동 확인 결과와 일치해야 다음 단계로 진행한다. 원문 값과 추출 규칙 버전을 남겨 셀렉터 변경 후 오염된 관측을 추적할 수 있게 한다.

페이지별 추출은 규칙 기반 파서로 처리하고 AI는 검증된 주간 자료 요약에만 사용해 토큰을 줄인다. 당장 사용자에게 필요한 API 키나 텔레그램 토큰은 없다. 반복 수집 단계에서는 Mac 상시 가용 시간과 기준 비교 상품·크기만 정하면 된다.

## 구현 진행 업데이트 (2026-09-14)

사용자 승인에 따라 첫 배포 범위를 ‘브라우저 검색 → 고정 옵션 등록 → 화면 텍스트 추출 → 사람 검토 → 저장’으로 확정했다. 확장 프로그램과 무인 워커는 이 흐름의 실사용 정확성을 검증한 후 진행한다.

- 종료된 API 검색 액션은 키 유무와 관계없이 410을 반환하며 외부 호출·검색 예약을 하지 않는다. 이전 검색 이력은 현재 가격이 아님을 표시해 보존한다. 운영 compose의 불필요한 쇼핑검색 키 전달을 제거한다.
- 브라우저 검색 링크와 브랜드스토어 URL을 지원한다. 기존 스마트스토어 키를 유지하고 브랜드스토어는 별도 호스트 구분 키를 사용한다. 두 호스트의 동일 판매자 자동 판별은 아직 지원하지 않으므로 중복 판매처 등록 여부를 직접 확인해야 한다.
- 패널에 크기 구분과 판매자 기준 문자열을 저장한다. 기존 자료에는 UNKNOWN과 빈 기준을 기본값으로 추가해 기록은 보존하고 대표 가격에서는 제외한다. 과거 자료를 임의로 재분류하지 않는다. 기준은 앞뒤 공백만 제거하며 단위 변환·범위 동치 추정은 하지 않는다.
- ‘상품 화면에서 가격 가져오기’는 30,000자 이내 텍스트를 브라우저에서 규칙으로 분석한다. 총 금액과 명확한 배송비를 읽고, 조건부 배송·서로 다른 금액·수량 1 초과는 미확인으로 남긴다. 붙여넣은 전체 원문은 서버로 보내지 않는다.
- 선택 옵션명 일치와 수량 1·쿠폰 제외 확인을 거쳐 기록 양식을 채운다. 재고는 별도 확인하고 기존 ‘관측 기록’ 버튼으로 저장한다. 메모에는 파서 버전·추출값·주의사항을 기록한다. API 호출을 통한 직접 수동 기록은 계속 지원한다.
- 저장 실패 시 입력 초안을 유지한다. 실제 페이지의 영역 구분은 운영자가 확인하는 첫 버전이며 무인 가격 확정 기능은 아니다.
