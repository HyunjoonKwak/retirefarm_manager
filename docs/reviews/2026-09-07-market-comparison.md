# 비교 조건 통일과 별칭 검토 도구

## 이번 구현 범위

품종·산지·포장 규격에 등급 조건을 추가하고, 조회·상세·분포 분석에 동일하게 전달한다. 산지 조건은 기존 부분 일치이며, 검증된 표준 산지코드로 바뀐 것은 아니다. 미확인 품종 별칭도 가격 조회에서는 원문별로 유지한다.

가격 추이와 일별 상세는 양수 가격·양수 수량인 거래만 사용해 `Σ(가격×수량)/Σ수량`으로 계산한다. kg 단가는 해석 가능한 포장의 `Σ(가격×수량)/Σ(포장kg×수량)`이다. `.5kg`, `500g`, `0.5kg`은 환산 가능하지만 `2kg×3` 등 복합 포장은 추정하지 않는다. 포장별 원가격을 하나의 규격으로 합치지는 않는다. 분포표는 수량 가중 중앙값과 25~75% 구간을 별도로 표시하고, 5건 미만 표본의 대표값은 계속 숨긴다. 조회 기간과 일자 키는 KST 기준으로 맞춘다.

비교 조건은 새 `MarketComparisonPreset`에 사용자별로 최대 50개 저장한다. 품목·품종 목록·산지·규격·등급을 원문 값으로 보존한다. 읽기·생성·삭제 모두 로그인 계정으로 제한하며 다른 계정의 조건을 삭제할 수 없다. 기존 브라우저 저장 조건을 사용자 확인 없이 계정으로 가져오지 않는다.

## 품종·산지 표준화 방법

1. `scripts/market-label-audit.cjs`로 원문별 거래 건수·기간·규격 조합을 추출한다. 원본 거래는 수정하지 않는다.
2. 공백·대소문자·유니코드 표기 차이, 품종명의 괄호·품목명 위치 차이를 후보로 묶는다. 후보 ID는 검토용이며 공인 표준코드가 아니다.
3. 원천 코드표 또는 산지·법인 담당자의 확인을 근거로 별칭을 승인한다. 유사한 문자열이나 가격만으로 같다고 확정하지 않는다. 특히 '일반', '기타', '도색', '적색', '찰'을 임의로 합치지 않는다.
4. 후속 매핑 테이블은 품목·분류축·원문·원천 범위와 표준코드, 확인 근거, 적용 버전을 저장하도록 한다. 조회 시 매핑을 적용해도 원문과 기존 거래 중복키는 보존한다. 취소 가능한 버전별 매핑과 미확인 상태가 필요하다.
5. 산지는 시도→시군→세부 산지 계층으로 확인한다. 단순 부분 일치와 표준 지역 포함 관계를 구별하고, 해당 기간 수집 기록이 없다는 것을 미출하·미생산으로 단정하지 않는다.

매핑 승인·편집 UI와 공인 코드 연결은 아직 구현하지 않았다. 이번 도구는 실제 자료로 후보를 만들고 원문을 검토하는 첫 단계다.

### 실행

로컬 환경(Node의 env-file 지원 필요):

```bash
node --env-file=.env scripts/market-label-audit.cjs --product 토마토 > tomato-label-audit.json
```

배포 이미지 내 환경 변수를 사용하는 경우:

```bash
docker exec retirefarm-app node scripts/market-label-audit.cjs --product 토마토 > tomato-label-audit.json
```

출력은 원문별 통계와 검토 후보 JSON이다. 가격 자료를 합치거나 DB에 쓰는 기능은 없다.

## 장기 집계 후속 설계

현재 원본 정리는 과거 거래를 직접 삭제한다. 일별 평균만 저장하면 향후 기간 중앙값을 복원할 수 없고, 품종·등급·규격·산지 필터가 바뀌면 재집계도 불가능하다. 따라서 다음 개발 묶음은 아래 완료 기준을 따른다.

- 원문 품목·품종·등급·규격·산지·법인·KST 일자별로 가격 분포와 수량을 보존한다. 평균은 금액 합계/수량 합계로, 중앙값은 가격 분포를 합쳐 계산하며 날짜별 평균·중앙값을 단순 평균하지 않는다.
- 같은 날짜를 재수집했을 때 원본과 집계가 중복 합산되지 않아야 한다. 현재 중복키에 수량이 포함된 의미까지 고려한 식별 방식과 집계 버전을 정한다.
- 검증된 집계 저장과 원본 삭제를 한 트랜잭션 또는 재개 가능한 단계로 묶는다. 거래 건수·수량·금액 대조가 실패하면 삭제하지 않는다.
- 자동 보관 정리와 관리자 수동 삭제를 구별한다. 명시적으로 삭제한 자료가 집계에서 다시 나타나지 않게 한다.
- 원본·집계가 겹치는 기간의 중복 제거와 자료 출처를 조회 API에서 일관되게 처리한다. 장기 구간에서 원문 상세를 제공할 수 없다면 명확하게 표시한다.
- 날짜별 수집 상태(성공/0건/부분/실패/미수집)를 자료 존재와 별도로 보존한다. 모든 법인의 완전 수집이 확인되지 않은 날은 '휴장'으로 채우지 않는다.
- 원본 정리 전후 1년 조회의 필터 결과·가중평균·분포 분위수·공백 표시가 같다는 통합 테스트가 배포 조건이다.

장기 집계 저장과 원본 정리 교체는 이번 변경에 포함되지 않았다. 승인 매핑·장기 집계가 끝나기 전까지 로드맵 3·4 전체 완료로 표시하지 않는다.

## 수집 설정 오류 보완

설정 저장 API에서 00:00~23:59 시각, 정수 요일(0~6) 최소 한 개, 정수 대상일(0~7)을 검증한다. 기존 잘못된 활성 설정은 본인의 자동 보충 응답에 구체적인 수정 안내를 반환한다. 준비 상태의 의미와 503 응답은 유지하며, 잘못된 설정을 정상 예약으로 간주하지 않는다.
