# 품종별 가격 분포를 의사결정 정보로 가공하는 설계

2026-09-06 / 제안·설계 단계. 운영 시세 분포를 측정한 결과가 아니다. 기존 수집 신뢰성 개선 이후 구현할 분석 방법과 화면 도구를 정의한다.

## 1. 현재 구조에서 부족한 점

`getProductPriceHistory`는 여러 품종을 `in` 조건으로 조회하지만, 조회 이후 품종·등급을 유지하지 않고 날짜별로 합친다(`src/lib/services/garak-market.ts:582` 이후). 반환 타입 `PriceHistory`도 평균·최고·최저·건수 위주로 중앙값과 분위수, 품종별 계열이 없다(`src/components/market/marketPriceTypes.ts:24`). 현재 API 결과만으로는 품종별 분포나 가격 차이의 원인을 복원할 수 없다.

가격 차이는 품종뿐 아니라 등급, 크기, 포장, 인증, 산지, 법인, 거래일, 수집 누락에서 생길 수 있다. 원/kg 환산은 중량 차이를 줄이지만 상품성이 같아지는 것은 아니다. 낮은 가격을 일괄 삭제하거나 전체 평균으로 평탄화하면 유용한 차이까지 지워진다.

## 2. 가공 단계

### A. 원본 보존과 품종 사전

- 원천 품목명·품종명·규격·등급·단위와 원천 거래 키(제공 시)를 보존한다. 정규화한 값은 별도 필드로 둔다.
- 공백·문자 표기 정리는 결정 규칙으로 처리한다. 별칭은 공급원별 사전으로 관리하고, 사전 버전·근거·검토 상태를 남긴다.
- 품종과 브랜드·산지·인증이 한 문자열에 섞인 경우 원문을 유지한 채 속성을 나눈다. 공급자 등급의 의미가 같다고 검증되지 않았다면 자동 통합하지 않는다.
- 이름이 비슷하거나 가격이 비슷하다는 이유만으로 서로 다른 품종을 합치지 않는다. 미상·혼합·매핑 미확인은 별도 그룹으로 표시한다.
- 관리 도구: `원천 표기 | 연결할 품종 | 등급/규격 해석 | 적용 건수 | 대표 원문 | 검토 상태`. 변경 전후 통계 차이를 미리 보고 적용할 수 있게 한다.

공식 [전국 경매 API 안내](https://www.data.go.kr/data/15141808/openapi.do)는 품목·시장·등급·포장 등의 표준코드 연계를 안내한다. 이를 사전의 기준으로 검토하되 현재 가락시장 문자열과의 실제 대응표는 표본 검증이 필요하다.

### B. 비교 가능한 거래 묶음

기본 비교 조건은 `거래일/기간 + 시장 + 품종 + 등급 + 포장 규격`이다. 산지·법인·인증은 분해 축으로 제공하고, 가격에 큰 영향을 주는 경우 저장된 출하 조건에 포함한다. 크기 등 원천에 없는 속성은 추정해 채우지 않는다.

- 첫 화면: 품목 안의 **품종별 행**을 유지하고, 같은 등급·포장 규격·기간을 고정해 비교한다.
- 원/kg 비교 모드: 중량이 확인된 거래만 환산하며 포장·등급별 세부 분포는 계속 볼 수 있게 한다. 개·단·상자처럼 중량이 불명인 거래는 원/개 등 별도 화면에 남긴다.
- 표본이 적으면 같은 조건의 최근 7일로 확장하는 선택지를 제시한다. 자동으로 다른 품종·등급을 합치거나 과거 값을 오늘 시세처럼 채우지 않는다.
- 품종·등급 통합을 사용자가 선택한 탐색 화면에는 ‘여러 조건 포함’을 표시하고 구성 비중을 함께 제공한다.

### C. 대표값은 중앙값, 범위는 분위수, 거래 규모는 별도 표시

각 거래 행 i에서 포장 가격 pᵢ, 포장 수 qᵢ, 포장 중량 kᵢ가 검증되어 있다는 전제다. 원천 QTY의 의미와 동일 내용 거래의 중복 제거 기준 검증이 먼저다.

| 지표 | 정의 | 사용 목적 |
|---|---|---|
| 중심 가격 | 중량 가중 중앙값 P50: 단가 xᵢ=pᵢ/kᵢ, 가중치 wᵢ=qᵢkᵢ | 거래된 물량의 가운데 가격 수준 |
| 주요 거래 구간 | 같은 가중치로 계산한 P25~P75 | 물량 기준 중앙 50%의 가격 구간 |
| 넓은 거래 구간 | P10~P90 | 충분한 표본에서 저가·고가 쪽 분포 확인 |
| 물량 가중 평균 | Σ(pᵢqᵢ)/Σ(qᵢkᵢ) | 전체 거래 금액과 물량을 반영한 평균 |
| 거래 규모 | 원천 거래 행 수, 총 kg, 거래일 수, 법인별 물량 비중 | 소수 거래나 한 법인 편중 확인 |
| 분포 폭 | P75−P25, 필요 시 (P75−P25)/P50 | 같은 조건 안에서 가격이 얼마나 퍼졌는지 |
| 데이터 품질 | 미분류·환산 제외 행 비율, 실패 페이지, 수집시각, 조건 적용 후 행 수 | 현재 요약의 범위와 누락을 확인 |

가중 분위수는 가격 오름차순으로 정렬한 후, 누적 가중치가 전체 가중치의 α 이상이 되는 최초 가격으로 정의한다. 중간값 보간은 하지 않는다. 동일 규격의 포장 가격 모드에서는 xᵢ=pᵢ, wᵢ=qᵢ를 사용한다. 표시 단계에서만 반올림한다. ‘거래 행’이 농가 수나 독립 표본 수라는 뜻은 아니다.

동일 가격에 물량이 몰린 이산 분포에서는 P25~P75 안의 실제 물량 비율이 정확히 50%가 아닐 수 있다. ‘중앙 50%를 나타내는 분위수 구간’으로 설명하고 필요 시 실제 포함 물량 비율을 함께 표시한다.

통상적인 상자그림은 중앙값과 사분위수로 분포를 요약한다([NIST](https://www.itl.nist.gov/div898/software/dataplot/refman2/auxillar/iqrange.htm)). 여기서 물량 가중치를 사용하는 것은 이 제품의 설계 선택이다. 범위는 **관측 거래 분포**이며 미래 가격 예측 구간이나 중앙값의 신뢰구간이 아니다. 최빈 가격대가 필요하면 구간 폭을 명시한 히스토그램을 별도로 보여준다. P25~P75를 ‘가장 많이 거래된 가격대’라고 부르지 않는다.

기간 요약에서는 물량이 많은 날의 영향이 커진다. 하루별 중심 가격 추이와 기간 전체 분포를 구분하며 ‘기간 평균’이라는 모호한 명칭을 피한다. 전체 기간 P50은 일별 P50을 평균해서 만들 수 없다.

### D. 이상 가격은 표시하고 원인을 찾아본다

1. 가격·수량 비양수, 해석 불가능한 단위·날짜는 검증 실패로 격리하고 사유를 기록한다. 정상 통계에는 포함하지 않지만 원본은 유지한다.
2. 같은 조건의 그룹 안에서 IQR 기준 등을 사용해 극단 가격 후보를 표시한다. 초기 후보 기준은 P25−1.5×IQR 미만 또는 P75+1.5×IQR 초과로 하되, 물량 가중 분위수에 적용하는 운영 규칙임을 명시한다.
3. 정상 거래는 극단적이어도 기본 통계에 포함한다. 후보 제외 보기는 사용자가 켜는 진단 옵션으로 제공하고, 제외 전후 가격·행 수·물량을 나란히 보여준다.
4. 분포가 두 덩어리로 갈리면 등급·규격·법인·산지별로 분해한다. 데이터가 지지하지 않는 원인은 ‘확인 불가’로 남긴다. 가격대 군집은 탐색용으로만 쓰고 품종·등급의 정답으로 사용하지 않는다.

[NIST의 상자그림 설명](https://itl.nist.gov/div898/software/dataplot/refman1/auxillar/boxplot.htm)도 치우친 분포에서 많은 이상 후보가 나타날 수 있음을 지적한다. 작은 표본·IQR=0에서는 자동 이상 판정을 중지하고 개별 거래를 보여준다.

### E. 표본과 비교 조건에 따라 표현을 제한한다

다음 수치는 **초기 제품 운영 기준 제안**이며 통계적 정확성을 보증하는 임계값이 아니다. 주요 품목의 실제 분포를 확인한 뒤 조정한다.

- 1~4행: 거래 점과 관측 범위만 표시. 대표 시세·이상 판정·가격 순위·자동 알림은 보류.
- 5~19행: 중심 가격과 P25~P75를 ‘표본 적음’과 함께 표시. P10~P90·자동 이상 판정·자동 알림은 보류.
- 20행 이상: 확장 분포 표시 가능. 단, 부분 수집·단일 행 물량 편중·미확인 규격을 별도로 판단하며 건수만으로 ‘신뢰도 높음’을 부여하지 않는다.
- 중량을 모르는 행이 있으면 환산 가능한 **행 비율**을 표시한다. 알 수 없는 중량을 분모에 넣어 물량 수집률을 계산하지 않는다. 서버가 알려준 전체 행 수 대비 조회율도 ‘전국 시장 대표성’과 구분한다.
- 자동 알림은 수집 완전성·최신성·저장된 동일 조건을 충족할 때만 평가한다. 임계값 주변에서 반복 발송되지 않도록 재진입 조건과 발송 간격을 둔다.

## 3. 가격 구성 변화와 실제 가격 변화 구분

품종별 단가가 그대로인데 고가 품종 거래가 늘면 품목 평균은 오른다. 기본 화면에는 품종별 동일 조건 등락과 물량 비중 변화를 따로 표시한다.

품목 전체 지수가 꼭 필요하면 기준 기간의 품종·등급·규격 비중을 고정한 가격 지수를 후속 단계에서 제공한다. 기준 바구니에서 빠진 그룹의 비중과 포함 범위를 표시하고, 임의로 남은 그룹에 비중을 재배분하지 않는다. 기준 바구니·계산 버전을 저장한다. 처음부터 모든 품목을 하나의 점수로 압축하지 않는다.

합성 예시: A품종 2,000원/kg, B품종 6,000원/kg이고 첫날 A 90kg/B 10kg, 다음날 A 10kg/B 90kg이면 품목 평균은 2,400→5,600원/kg(+133.3%)이다. 두 품종 가격 변화는 각각 0%다. 화면은 ‘고가 품종 물량 비중 10%→90%’와 각 품종 0%를 보여줘야 한다. 실제 시장 데이터 예시가 아니다.

## 4. 만들 도구: 품종 비교 분석 화면

### 사용자 도구

상단에서 `품목 → 기간·시장 → 등급·규격 → 품종 비교`를 선택한다. 원/kg 또는 같은 포장 단위 중 비교 기준을 항상 보이게 한다.

| 품종 | 중심 가격 | 주요 거래 구간 | 거래량/행 수 | 동일 조건 등락 | 상태 |
|---|---|---|---|---|---|
| 품종별 한 행 | P50 | P25~P75 가로 구간 | kg·건수 | 비교 가능한 두 기간 | 표본 적음·부분 수집 등 |

행을 누르면 가격 분포, 법인·산지·규격별 구성, 원천 거래를 펼친다. 기본 정렬은 내 관심 품종 또는 거래량이며 가격만으로 ‘추천 품종’ 순위를 만들지 않는다. 데스크톱은 가로 구간 비교표, 모바일은 품종 카드와 최대 2~3개 고정 비교로 시작한다.

Claude의 후속 화면 검토를 반영해 품종별 분포 모드를 기존 차트에 추가하는 방식을 제안한다. P10~P90을 수염으로 쓰면 통상적인 IQR 수염과 다르므로 범례에 정확히 표시한다. 두 가격 덩어리가 보인다는 사실만으로 ‘산지 때문’이라는 배지를 붙이지 않는다. 휴장·미수집·표본 부족 구간은 추세를 끊고 0이나 직전 값으로 채우지 않는다. 원천 상세는 `dailyDetail` 경로이며 `daily`는 집계라는 점을 구현 시 구분한다.

`내 출하 조건으로 저장`하면 품종·등급·규격·비교 시장을 관심 품목과 알림에 연결한다. 요약 문구는 계산 결과로 생성한다: ‘같은 규격의 중심 가격은 X, 주요 거래 구간은 Y~Z, 이번 자료는 N행이며 일부 수집 상태입니다.’ 인과관계가 검증되지 않은 ‘수요 급증 때문’ 같은 해설은 생성하지 않는다.

### 구현 도구와 데이터 계약

- 기존 TypeScript 서비스에 정규화·그룹화·가중 분위수 순수 함수를 추가하고 서버에서 계산한다. 기존 Recharts와 표 컴포넌트를 활용할 수 있는지 확인해 불필요한 분석 플랫폼 도입을 줄인다. 외부 분석 서비스는 MVP 필수 요건이 아니다.
- 제안 API `GET /api/market/garak/analysis`: 기간·시장·품종·등급·규격·표시 단위와 그룹 축을 받아 행별 `p10/p25/p50/p75/p90`, 가중 평균, 행 수, 물량, 비교 가능 여부, 품질 사유, 정규화/통계 버전을 반환한다. 현재 구현된 API가 아니다.
- UI에 원본 전체를 전송하지 않고 요약과 페이지 단위 상세 조회를 분리한다. 상세에서 필터·제외 사유를 그대로 재현할 수 있어야 한다.
- 일별 집계에 평균·분위수만 보관하면 나중에 기간별 분위수를 정확하게 재계산할 수 없다. 단가별 물량 집계를 보관하거나 검증된 병합 가능 분위수 요약을 검토한다. MVP는 원본 보관 기간 내 정확 계산, 장기 분포는 별도 보관 설계 이후 제공한다.
- AI는 별칭 연결 후보와 사람이 읽는 설명 초안에 한정해 고려한다. 가격 계산·이상치 삭제·품종 확정은 결정 규칙과 검토 기록으로 처리한다. 실제 표본에서 필요성이 확인된 경우에만 군집·회귀 등 추가 분석을 도입한다.

## 5. 구현 순서와 검증

### 추가 UI: 산지에 따라 품종 선택지를 좁히기

**채택 제안:** 산지를 선택하면 해당 산지에서 조회 기간 내 거래가 확인된 품종을 강조하고 먼저 표시한다. 기본은 ‘거래 확인 품종’ 보기이며 ‘전체 품종 보기’로 다른 품종의 상태도 확인할 수 있다. 산지를 바꾸어도 품종이 모두 같은 상태로 남아 사용자가 빈 결과를 반복 조회하는 문제를 줄인다.

현재 `getProductVarieties`·`getProductOrigins`는 품목만으로 전체 보관 기간의 목록을 가져온다(`src/lib/services/garak-market.ts:755,771`). `MarketPriceManager.tsx:258`도 품목명만 전송하며, `MarketPriceFilter.tsx:66` 이후 품종 버튼에는 산지별 거래 상태가 없다. 따라서 UI 스타일 변경에 앞서 조건별 선택지 조회가 필요하다.

#### 화면과 상태 규칙

화면 순서는 `품목 → 기간·시장 → 산지 → 품종 → 등급·규격`으로 두고, 품종 영역에 ‘선택 산지 · 조회 기간 · 수집 자료 기준’을 명시한다. 예시 아래 품종 A/B/C는 가상 항목이다.

| 품종 상태 | 표시 예시 | 동작 |
|---|---|---|
| 선택 산지·기간에 거래 행 있음 | `품종 A · 거래 확인 · 24건` | 강조하고 선택 가능. 이미 선택한 상태는 체크 표시로 별도 구분. |
| 산지·기간에는 있으나 등급/규격 조건에서 0건 | `품종 B · 현재 규격 결과 없음` | 전체 보기에서 이유와 ‘규격 조건 해제’ 제공. 현재 조건의 신규 선택은 비활성. |
| 같은 산지에 과거 거래만 있음 | `품종 C · 기간 내 기록 없음 · 마지막 거래일 …` | 전체 보기에서 표시하고 기간 확장 동작 제공. 현재 기간 신규 선택은 비활성. |
| 해당 산지에서 수집된 기록을 찾지 못함 | `산지 거래 기록 미확인` | ‘생산되지 않는 품종’으로 표현하지 않음. 과거 자료/다른 산지 탐색으로 연결. |
| 선택지 조회 실패 또는 수집 누락 때문에 판단 불가 | `확인 필요` | 조회 실패를 0건으로 바꾸지 않음. 신규 선택을 확정적으로 막지 않고 전체 탐색과 재시도 제공. |

거래가 1건이라도 있으면 탐색은 가능하다. 다만 대표 시세·통계·알림의 표본 기준은 별도로 적용한다. 부분 수집에서도 확인된 거래의 존재는 표시할 수 있지만, 관측되지 않은 품종의 부재를 확정할 수 없다. 거래 건수는 수집된 행 수이며 해당 산지 전체 생산·출하 규모가 아니다.

‘현재 출하 중’ 대신 **‘조회 기간 내 거래 확인’**을 기본 문구로 쓴다. 경매일·수집시각·자료의 출처를 제공하며, 실시간 생산·출하 여부는 별도 출하 정보 없이는 확정하지 않는다.

#### 산지 변경과 기존 선택 처리

- 산지·기간 변경 시 그 조건에 맞는 선택지와 차트 데이터를 함께 갱신한다. 다른 산지의 이전 응답이 늦게 도착해 새 화면을 덮지 않도록 요청 취소 또는 요청 키를 사용한다.
- 기존 선택 품종이 새 조건에서도 조회되면 유지한다. 결과가 없어지면 선택 칩을 그대로 남기고 ‘현재 조건 결과 없음’을 표시한다. 몰래 선택을 삭제하거나 다른 품종으로 교체하지 않는다.
- 예를 들어 A/B를 선택했다가 새 산지에 A만 있으면 A 결과와 B의 빈 상태를 각각 보여준다. ‘결과 없는 선택 해제’ 버튼으로 사용자가 B를 제거할 수 있게 한다. 이전 B 시세를 새 산지 시세처럼 남겨두지 않는다.
- 선택 품종이 모두 무효여도 자동으로 전체 품종 조회로 넓히지 않는다. ‘품종 선택 해제’·‘기간 확장’·‘산지 해제’를 명시적으로 제공한다.
- ‘산지 전체’로 돌아가면 품종 목록을 다시 계산한다. 프리셋을 불러올 때도 동일 규칙으로 유효성을 확인한다.
- 강조색과 선택색을 다르게 쓰고, 글자 배지·체크·보조 설명을 함께 제공한다. 비활성 사유는 마우스 툴팁에만 두지 않고 모바일과 키보드에서도 읽을 수 있게 한다. 갱신 중임을 표시해 옛 목록을 새 결과로 오인하지 않게 한다.

#### API와 산지 사전

제안 `GET /api/market/garak/facets`는 품목·산지·시작/종료일·시장·등급·규격을 받아 품종별 다음 값을 반환한다. 현재 존재하는 API가 아니다.

`varietyId/name`, `originPeriodCount`(등급·규격 제외), `matchingCount`(현재 등급·규격 포함), `lastSeenAt`, `availability`, `reason`, `collectionState`, `asOf`, `filterKey`.

품종 후보를 셀 때는 **현재 선택된 품종 필터만 제외**한다. 그래야 A를 선택해도 B를 추가 선택할 수 있다. 산지 후보 목록은 MVP에서 품목·기간·시장 기준으로 유지하고, 선택한 품종 때문에 산지가 사라지는 상호 제한은 도입하지 않는다. 품종과 산지의 다중 선택은 각 차원 안에서 OR, 다른 차원 사이에서 AND로 정의한다. 첫 구현은 현재처럼 산지 단일 선택으로 충분하다.

산지 문자열의 `contains` 검색을 생산 지역의 계층 구조로 간주하지 않는다. 표시용 원문을 보존하고 시도·시군구 코드와 별칭을 검증해 연결한다. ‘충남 전체’는 검증된 하위 지역 집합으로 조회하고, 매핑되지 않은 산지는 ‘미분류’로 남긴다. 검색은 후보를 찾는 용도, 실제 선택은 명확한 산지 식별자로 처리한다. 기존 저장 프리셋에는 이전 문자열의 재매핑 상태를 표시한다.

서버에서 한 번의 그룹 집계로 목록과 건수를 계산하고 조건·수집 버전을 기준으로 캐시한다. 실제 부하를 측정한 뒤 인덱스를 정한다. 수집 또는 품종/산지 사전 변경 시 캐시를 갱신한다. 선택지 조회 범위와 차트 범위가 같아야 하며, 분석 요약과 동일한 정규화·유효 거래 규칙을 사용한다.

#### 이 UI의 인수 기준

1. 산지 X에 A만 있고 Y에 B만 있는 표본에서 X 선택 시 A만 ‘거래 확인’으로 표시된다.
2. A 선택 후에도 같은 산지의 다른 조회 가능한 품종을 추가 선택할 수 있다.
3. 산지에는 존재하지만 기간/규격 때문에 0건인 품종의 사유가 구분된다.
4. 산지 변경 시 이전 선택을 무단 삭제하거나 이전 산지 가격을 재사용하지 않는다.
5. 수집 누락·요청 실패가 ‘미생산’·‘출하 안 함’·확정 0건으로 표시되지 않는다.
6. 빠른 산지 전환, 프리셋 복원, 산지 전체 해제에서도 최종 조건과 목록·차트가 일치한다.
7. 강조·선택·비활성을 색상 없이도 구별하고 비활성 이유를 키보드·모바일로 확인할 수 있다.

이 항목은 품종 비교표의 첫 구현에 함께 포함한다. 작은 화면 동작 검토이므로 추가 Claude 호출 없이 기존 공동 설계를 바탕으로 Codex가 현재 코드를 확인해 확장했다.

1. 기존 로드맵의 수집 실패/부분 상태와 단위 계산부터 수정한다.
2. 품종 분리·동일 규격 필터·P50/P25/P75·물량·표본 표시를 첫 분석 기능으로 구현한다.
3. 품종 비교 화면과 원천 거래 드릴다운, 출하 조건 저장을 연결한다.
4. 별칭 관리, 이상 후보 진단, 구성 비중 변화 설명을 추가한다.
5. 충분한 이력이 쌓인 뒤 고정 구성 지수·장기 계절 분포·판매 실적 비교를 검토한다.

필수 검증 사례:

- 같은 품종·규격의 거래 행을 같은 가격의 여러 행으로 나눠도 가중 가격과 분위수가 변하지 않는다. 행 수 표시만 달라진다.
- 5kg 10,000원과 10kg 20,000원은 2,000원/kg이다. 포장 구성 변화로 원/kg 등락이 발생하지 않는다.
- 위 A/B 예시에서 품목 평균은 바뀌어도 각 품종 등락은 0%이며 두 행이 유지된다.
- 극단 가격 1건이 있어도 원본에서 사라지지 않고, 후보 제외 옵션의 영향이 숫자로 확인된다.
- 미상 품종·환산 불가·부분 수집·표본 부족이 정상 0원이나 무거래로 변환되지 않는다.
- 거래일·품종·등급·단위가 다른 비교는 차단하거나 조건 차이를 명시한다.
- 일별 중앙값의 평균을 기간 중앙값으로 표시하지 않는다.

첫 인수 기준은 ‘내 품종의 같은 출하 규격에서 어느 가격 구간에 얼마나 거래됐고, 비교 가능한 이전 기간보다 어떻게 달라졌는지’를 원천 거래까지 설명할 수 있는 것이다.
