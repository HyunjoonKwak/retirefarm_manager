# 7월 22일 이후 시세 수집 중단 조사

## 확인한 원인

파일 배치 기준: [Next.js 공식 instrumentation 문서](https://nextjs.org/docs/app/api-reference/file-conventions/instrumentation). 설치된 빌드 코드와 실제 배포 산출물을 함께 대조했다.

- NAS DB의 토마토·방울토마토·포도 마지막 거래일과 수집 로그가 모두 2026-07-22였다. 자동 수집 설정은 활성화되어 있었고, 매일 09:30 KST 당일·토마토/포도·6개 법인으로 설정되어 있었다.
- 7월 22일 커밋 `4826b3e`에서 초기화를 서버 부팅 instrumentation으로 일원화했다. 앱은 `src/app`에 있었지만 초기화 파일은 루트에 있었다.
- NAS에 남아 있던 8월 20일 운영 이미지 `efc602b6972d`(Next.js 16.0.8)를 네트워크·DB 마운트·운영 환경변수 없이 파일 검사 전용 컨테이너로 확인했다. `.next/server/instrumentation.js`가 없었다. 예약 작업이 부팅 시 등록되지 않는 배포 결함이 중단 기록과 일치한다. 7월 22일 당시 컨테이너 로그는 남아 있지 않아 그날의 프로세스 상태 자체를 재현한 것은 아니다.
- 로컬 Next.js 16.3.4의 `.next/server`에는 초기화 번들이 있었지만 `.next/standalone` 복사에서 누락됐다. NAS의 직전 16.3.4 실행 컨테이너에서도 파일 부재를 확인했다. 개발 산출물과 배포 산출물을 혼동하면 발견하기 어려운 문제였다. 초기화 파일을 `src/instrumentation.ts`로 옮기고 Docker 빌드가 실제 standalone 초기화 파일 없이는 성공하지 않게 검증을 추가했다.
- 운영 컨테이너에서 가락 API에 인증된 HTTPS 1페이지 요청을 했다. 7월 23일·9월 5일 서울청과 토마토가 각각 총 434·480건으로 정상 응답했다. 자격증명과 원문 응답은 로그에 출력하지 않았다.

## 추가로 확인한 수집 오류

실제 `pagesize=10`은 10행, `100`은 100행, `1000`도 최대 100행을 반환했다. 기존 코드는 요청은 1000, 계산은 10으로 고정해 불필요한 페이지를 요청하고 정상 수집도 부분 수집으로 오판했다. 요청과 계산을 100으로 통일했고 480건을 5번 요청하는 회귀 테스트를 추가했다. 최대 100페이지라는 보호 상한은 유지한다.

## 복구와 재발 방지

- 우선 9월 5일 거래 4,745건을 신규 저장했다. 이 첫 복구는 페이지 계산 수정 전이라 PARTIAL 로그가 남았다. 수정본으로 재확인한다.
- 초기화 파일 위치, 전역 스케줄러 상태, 부팅 로그와 상태 API를 보완해 웹 서버만 살아 있고 예약 작업이 없는 상태를 확인할 수 있게 한다.
- 최신 자료가 3일 이상 오래되면 화면에서 거래 부재 또는 수집 상태를 확인하도록 안내한다. 오래된 자료가 곧 장애라고 단정하지 않는다.
- `scripts/market-backfill.cjs --from 2026-07-23 --to 2026-09-06`: 기존 인증된 내부 수집 API를 호출한다. 최신 날짜부터 순차 처리하며 완료한 날짜/조건의 기록을 남겨 재시작 시 건너뛴다. 과거 자료를 삭제하지 않는다. 최대 62일로 제한하고 실패 시 중단한다.
- 복구 이력은 NAS 컨테이너의 영속 DB 디렉터리 `market-backfill.jsonl`에 보관한다. 부분 수집은 완료로 표시하지 않는다.
