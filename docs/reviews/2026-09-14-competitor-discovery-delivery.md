# 경쟁 판매처 추천 후보 1차 구현

## 구현 범위

리포트 → 경쟁점 조사 → **경쟁 판매처 추천 후보**에서 검색 근거를 저장하면 자동 평가하여 최대 10개 판매처를 추천한다. 이번 구현은 사람의 검색 관측 입력과 후보 평가·저장·검토 단계다. 스스로 검색 화면을 방문하는 워커와 주간 예약은 아직 구현하지 않았다.

- 검색어·관측 시각·결과 위치·광고 여부·품목 일치 여부·공개 구매 표기·리뷰 수와 집계 기준을 저장한다. 미확인 값은 그대로 보존한다.
- 검색어별 최신 자료만 사용하고 최근 7일 안에 확인한 비광고·품목 일치·위치 확인 자료로 평가한다. 같은 검색어 반복 입력은 노출 횟수를 부풀리지 않는다.
- 확인된 검색어 수 내림차순, 최상위 관측 위치 오름차순으로 평가하고 동일 판매처는 한 상품만 추천한다. 실제 판매량·검색량 또는 시장 전체 순위를 산출했다고 표시하지 않는다.
- 공개 구매 표기는 설명용이며 숫자로 추정해 점수에 더하지 않는다. 리뷰 증가는 누적 전체 리뷰의 비교 가능한 과거 관측이 있을 때만 계산한다. 이동 기간 집계나 감소·집계 충돌은 미확인으로 남긴다.
- 후보의 판매처·상품 URL만 기존 고정 비교 양식에 채운다. 선택 옵션·품종·중량·크기 기준은 사람이 확인하며, 후보 저장만으로 고정 패널이나 가격 관측이 생성되지 않는다.
- 이미 고정 비교 중인 판매처는 전체 후보에서 볼 수 있지만 새 추천 10자리를 차지하지 않는다.
- 판매처 추천 제외·재검토 사유와 변경 이력을 보존한다. 제외는 같은 판매처의 기존 후보와 이후 발견된 다른 상품에도 적용한다. 기존 고정 비교 목록과 관측 기록은 유지한다.

## 저장·검증

추가 테이블은 CompetitorDiscoveryRun / Candidate / Evidence / Decision 네 개다. 사용자별 후보 URL 고유 제약과 입력 자료 해시로 재시도 중복을 막는다. 같은 상품·검색어·시각에 상충하는 자료는 전체 가져오기를 롤백하고 오류로 알린다. 과거 자료를 뒤늦게 가져와도 최신 제목·마지막 확인 시각을 덮어쓰지 않는다.

입력은 정확한 HTTPS 스마트스토어·브랜드스토어 상품 URL만 허용하고 추적 쿼리를 제거한다. 미래 또는 30일 초과 관측은 거부한다. 한 번에 최대 60개 근거, 요청 256KB, 하루 60회 새 가져오기, 사용자별 후보 500개로 제한한다. 평가는 최근 15일 중 상품별 최신 120개 근거를 사용한다. DB 변경은 신규 테이블 추가만 포함한다.

검색 후보 파일은 `POST /api/briefings/discovery`의 `action: import, evidence: [...]` 형식이다. 기존 `retirefarm-visible-product-v1` 상품 가격 수집 파일과 혼동하지 않게 거부한다. 이 후보 입력 경로는 현재 로그인한 사용자의 자료만 다룬다.

```json
{
  "action": "import",
  "evidence": [{
    "productUrl": "https://smartstore.naver.com/실제판매자영문ID/products/실제숫자ID",
    "storeName": "직접 확인한 판매처 이름",
    "title": "직접 확인한 상품 제목",
    "query": "직접 사용한 검색어",
    "observedAt": "실제 관측 시각의 ISO 8601 문자열",
    "position": null,
    "adStatus": "UNKNOWN",
    "relevance": "UNKNOWN",
    "purchaseLabel": "",
    "reviewCount": null,
    "reviewBasis": "UNKNOWN"
  }]
}
```

위 예제의 주소·시각은 설명용 자리 표시자여서 그대로 가져올 수 없다. 공개 화면에서 관측한 값으로 교체한다. 검색 환경·정렬별 관측 분리는 후속 검색 화면 수집 계약에서 추가할 예정이다. 현재 입력은 같은 검색어의 최신 관측만 유지해 평가하므로 서로 다른 검색 환경을 독립적인 반복 노출로 간주하지 않는다.

## 후속 우선순위

1. 검색 결과 전용 브라우저 수집 도구와 검색 환경·정렬·원본 검색 주소의 근거 계약을 추가한다. 현재 상품 전용 확장은 그대로 가격 확인에 사용한다.
2. 실제 검색어 3개 × 첫 20개 결과로 URL·광고 여부·품목 분류를 대조한다. 광고 여부를 확인할 수 없는 결과는 자동으로 비광고 처리하지 않는다.
3. 동일 옵션 3–5곳에서 반복 가격 정확성을 검증하고 주간 Mac 워커의 단계별 재개·실패 표시·중복 실행 방지를 연결한다.
4. 추천 후보 변화와 고정 비교 가격의 주간 보고서 통합, 운영 일정 설정을 추가한다. 최소 두 차례 주간 시험 후 무인 운영으로 전환한다.

후보 선정은 규칙 기반으로 실행하여 AI 토큰을 소비하지 않는다. Claude가 계약·추천 규칙과 저장 API 통합 테스트를, Codex가 DB·API·화면·통합·배포를 담당했다.

- 전체 Vitest 66개 파일, 685개 테스트 통과.
- 신규 추천 규칙 45개, 실제 SQLite/Prisma 저장·API 통합 22개, 추천 UI 6개 테스트 포함.
- 타입 검사, 변경 파일 ESLint 및 diff 공백 검사 통과.
