# 보안 확인 이후 검색 수집 검증

## 확인한 결과

2026-09-14 17시경, 사용자가 네이버 보안 확인을 직접 완료한 뒤 동일 검색 탭에서 대추방울토마토 2kg 결과를 읽었다. 탭을 추가하지 않고 추천순 → 판매 많은순 버튼 전환을 확인했다. 선택 정렬의 접근성 이름이 판매 많은순 선택됨으로 바뀌었다. 실제 판매량 수치를 확보한 것은 아니다.

실제 버튼은 본문·aria-label이 없고 aria-labelledby로 같은 li 안의 sort_RECOMMEND 또는 sort_PURCHASE를 참조한다. 참조 대상에는 정렬 이름과 접근성용 선택됨 표기가 들어 있다. 1.1.0은 이를 읽지 못해 UNKNOWN으로 기록하는 문제가 있었다.

1.1.1에서는 같은 보이는 제어 그룹 안의 짧은 연결 레이블을 읽도록 수정했다. 다른 그룹·숨겨진 레이블·과도한 길이는 거부하고, 서로 다른 선택 상태가 있으면 UNKNOWN으로 남긴다. 추적용 data 속성으로 상태를 추측하지 않는다.

일반 상품 카드의 부모 안에 정보 영역 1개, main/products 상품 링크, 판매처 outlink가 함께 있는 구조도 DOM에서 확인했다. 조합 주소는 여전히 상품 상세 페이지에서 확인해야 한다.

## 검증 범위

- 실제 브라우저 DOM과 선택 상태 확인 완료.
- 확장 관련 회귀 테스트 95개 통과.
- 설치된 확장을 통한 JSON 내보내기와 앱 가져오기 전체 흐름은 아직 별도 확인 필요.
- 확장 관리 페이지 접근은 브라우저 도구의 URL 정책으로 차단됐다. 우회하지 않고 사용자에게 설치 여부·JSON 저장 가능 여부를 요청했다.
- 검색 탭은 1개만 유지한다. 보안 확인 재발 시 자동 재방문하지 않는다.

## 다음 개발 준비

기존 src/lib/briefing/queue.ts는 브리핑 스냅샷을 받아 AI 분석을 수행하는 큐다. 10분 실행 임대, heartbeat, 소유권 검증, 최대 3회 시도, 인증·제한 차단 처리가 이미 있다. 검색 수집 작업을 이 큐에 그대로 넣으면 입력·완료 의미가 달라지므로 별도 수집 작업 모델과 계약을 두고 소유권·재시도 패턴을 재사용한다.

수집 상태 기본안은 대기 → 실행 → 사용자 검토 대기 → 완료이며, 보안 확인·로그인 필요·화면 변경·시간 초과를 별도 사유로 기록한다. 브라우저 미실행은 수집 성공이나 빈 결과로 기록하지 않는다. 사용자 검토 전에는 검색 자료를 가격 관측으로 전환하지 않는다.

실행 키는 사용자·주차·검색 설정 버전으로 구성하고 검색어별 진행 위치를 남긴다. 보안 확인에서는 같은 탭을 보존해 사용자 확인 후 명시적으로 재개하며, 중복 새 탭을 만들지 않는다. 네트워크 일시 오류만 제한적으로 재시도한다. 기존 고정 비교 목록은 자동 교체하지 않는다.

구현 순서는 실자료 JSON 왕복 검증 → 수집 큐·상태 표시 → 검색어 3개 시험 → 동일 옵션 3–5개 판매처 가격 확인 → 주간 실행·보고서 연결이다. 이번 수정은 정렬 인식 보완이며 예약 수집 구현 완료를 의미하지 않는다.

## 운영 앱 가져오기·저장 확인 완료
