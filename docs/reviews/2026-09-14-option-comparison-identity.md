# 옵션 비교 기준 보강

## 문제와 변경

실제 검색 자료에는 1kg·2kg·다박스 증정·일반·스테비아·컬러 혼합 상품이 함께 있었다. 같은 상품 URL 안에서도 루체(주황) 2kg와 엠버(노랑) 2kg의 추가금이 달랐다. 기존 품종 그룹(JUJUBE/ROUND), 품질, 중량, 크기 기준만으로는 품종명·색상·가공 차이를 구분하지 못했다.

고정 패널에 확인한 품종명, 과실 색상, 단일/혼합 여부, 가공 여부를 추가한다. 모든 새 값은 기본 미확인이며 제목·사진·AI 추정에서 자동 입력하지 않는다. 확인 체크 이후 필드를 수정하면 체크를 해제한다.

## 대표 가격 조건

- 기존 품목·품종 그룹·품질·중량·크기 등급·판매자 크기 수치 기준에 더해 확인한 품종명·색상·가공이 정확히 같아야 한다.
- 앞뒤 공백만 정리한다. 품종 별칭, 표기 변형, 서로 다른 크기 단위를 자동 합치지 않는다.
- 색상/가공 기타 또는 미확인, 품종명 미확인, 혼합 또는 혼합 여부 미확인은 기록만 보관하고 통계에서 제외한다. 혼합은 구성 품종과 비율이 없으면 동등성을 검증할 수 없다.
- 무가공 생과·스테비아·자일리톨을 각각 별도 그룹으로 나눈다. 스테비아 표기를 품종명으로 자동 사용하지 않는다.
- 최근 7일 재고 있음·양수 판매가·배송비 확인·서로 다른 3개 판매처 요건과 동일 패널의 전주 비교 요건은 유지한다.
- 기록 시 가격은 선택 옵션 1개의 확인 금액이어야 한다. 쿠폰/증정/회원 조건은 관측 메모에 별도로 기록한다.

## 기존 데이터와 제한

DB는 4개 컬럼을 추가하며 기본값은 빈 품종명/UNKNOWN이다. 과거 가격이나 후보 데이터를 수정하지 않는다. 기존 정보가 부족한 패널은 통계에서 제외되며, 조건 확인 후 기존 항목을 보관하고 재등록한다. 이전 관측을 새 옵션에 소급 연결하지 않는다.

현재 판매처당 활성 옵션 하나, 최대 30곳 규칙은 유지한다. 같은 판매처의 복수 옵션 추적과 동일 그룹 내 판매처 중복 처리 정책은 별도 후속 변경이 필요하다. 새로운 기준을 채우지 않고도 자료 보관과 가격 기록은 가능하지만 대표 가격에는 포함되지 않는다.

## 다음 개발 순서

1. 후보 20곳에서 실제 판매 옵션의 속성/중량/배송비를 확인해 비교 가능한 패널 확보. 판별 근거가 없으면 미확인으로 보관한다.
2. 판매처당 복수 옵션 식별자를 도입하고 옵션 변경 시 과거 관측의 비교 일관성을 보장한다.
3. 혼합 상품 구성/비율, 쿠폰·회원가·다박스 증정 조건을 구조화한다.
4. 브라우저 수집 워커와 주간 예약을 연결하되 보안 확인/로그인 중단과 재개 상태를 기록한다.
5. 주간 보고서에 비교 가능한 점포 수, 미확인/제외 이유, 관측일, 동일 패널 전주 변화와 원본 링크를 함께 표시한다.

Claude는 DB·계약·통계·백엔드 테스트, Codex는 입력 UI·확인 해제·표시·UI 테스트 및 배포를 담당한다.
