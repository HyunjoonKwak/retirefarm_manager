# 주간 브리핑 수집 확인·기간 비교

## 구현 범위

리포트 → 주간 브리핑의 **시세 분석 미리보기**는 서버 집계만 실행한다. AI 호출·작업 등록·보고서 저장이 없으며 필터를 변경하면 기존 미리보기를 지운다. 초안 생성 시에는 같은 분석을 불변 스냅샷에 넣어 화면과 Mac 워커가 함께 사용한다. 이전 보고서는 다시 계산하거나 변경하지 않는다.

- 보고 주간: 지난 완결 KST 월요일부터 일요일까지.
- 전주: 보고 주간 바로 앞의 완결 주.
- 직전 네 주: 보고 주간을 제외한 이전 28일의 전체 유효 거래를 수량 가중한 기준가. 주간 평균의 단순평균이 아니다.
- 비교 조건: 법인 코드·법인명·품목·품종·산지·등급·거래단위가 모두 일치하는 그룹. 이번 보고 주간에 관측된 그룹만 비교한다.
- 값: `SUM(price × quantity) / SUM(quantity)`; 양수 가격·수량만 사용. 단위 환산이나 공개 일평균과의 혼합은 하지 않는다. 한 SQL 집계로 다섯 주를 계산하고 그룹 상한 초과 시 조건 축소를 요구한다.

## 수집 확인의 의미

날짜×법인마다 해당 품목을 포함하는 최신 로그를 확인한다. 복수 품목은 쉼표 구분의 정확한 토큰으로 판단하며 null/공백은 전체 품목이다. 완료시각, 시작시각을 기준으로 최신 로그를 고르고 같은 시각이면 더 보수적인 상태를 사용한다. 미래 로그는 제외하며 완료시각이 없는 최신 기록은 미확인이다.

| 표시 | 의미 |
|---|---|
| 완료 기록 | SUCCESS 또는 EMPTY 로그가 있는 슬롯 수 |
| 빈 응답 | 완료 기록 중 EMPTY인 슬롯. 휴장·실제 무거래를 보증하지 않음 |
| 부분·실패 | 적용 로그가 PARTIAL 또는 FAILED |
| 미확인 | 기록 없음·완료시각 없음·인식할 수 없는 상태 |

요일·공휴일을 보고 휴장을 추정하지 않는다. 통합 품목 로그가 PARTIAL이면 개별 품목의 성공 여부를 분리할 수 없어 보수적으로 판단한다. 로그 성공은 원자료의 현재 보존 상태나 시장 전체 완전성을 보증하지 않는다.

## 등락률 표시 조건

양쪽 기간에 해당 법인·품목의 모든 날짜별 수집 완료 기록이 있고, 동일 그룹의 각 기간에서 **거래 세 건·관측 이틀 이상**일 때만 등락률을 표시한다. 기준 가격은 반올림 전에 계산한다. 다른 법인의 수집 누락이 해당 그룹 비교를 막지는 않는다.

자료가 없으면 `NO_BASELINE`, 표본이 작으면 `LOW_SAMPLE`, 수집 확인이 부족하면 `UNVERIFIED_COLLECTION`로 사유를 표시하고 등락률은 null로 둔다. 원자료 평균과 건수·관측일 수는 함께 보여준다. 최소 표본 기준은 작은 표본 오해를 줄이기 위한 제품 규칙이며 통계적 유의성이나 예측 신뢰도를 뜻하지 않는다.

## 계약·호환성과 검증

DB migration은 없다. 기존 snapshot v1에 선택적인 `analysis.version=1`을 추가했다. 서버와 Mac 워커는 `scripts/briefing-analysis-schema.mjs`를 공유한다. 구버전 초안에는 분석 미포함 안내를 표시한다. 기존 계산 정의는 유지하며 새 입력에는 수집 확인·비교 자료가 추가되므로 새 요청의 입력 해시는 달라질 수 있다.

검증 범위: KST 경계, 최신 실패·재수집 성공, 품목/법인 범위, EMPTY/미확인 구분, 전주·네 주 구간 분리, 다른 품종 제외, 가중평균·등락률, 표본 부족, 수집 실패 시 등락률 보류, 서버/워커 스키마 일치, 미리보기의 인증·작업 미생성·필터 변경 시 초기화. Claude는 수집 확인 함수와 테스트, Codex는 집계·계약·UI·통합 검증을 담당했다.

## 남은 작업

기존 Work의 공개 일평균 시계열·원문/정정 이력 이전, 거래일 달력의 명시적 근거 연결, 수집 누락 복구, 산지별 관측 품종 선택, 중앙값·분포·이상치 표시가 남았다. 이번 구현은 원자료 가중평균의 비교이며 전체 Work 보고서를 대체하지 않는다. 자동 예약과 텔레그램은 활성화하지 않는다.
