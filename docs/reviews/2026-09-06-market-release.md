## 후속 개선 범위

- 품종·등급·포장 규격을 분리한 비교표: 물량 가중 중앙값과 P25~P75, 원/kg 전환, 거래량·행 수, 최근 원천 거래 최대 5행.
- 5행 미만은 대표 가격을 보류하고 20행 미만은 표본 적음 표시. 원천 가격·수량이 유효하지 않으면 제외 건수를 알린다. 극단 가격을 자동 삭제하지 않는다.
- 기간 분석은 서버에서 처리하고 최근 20,000행을 상한으로 둔다. 상한 도달 시 불완전 범위임을 표시하고 조회 조건 축소를 안내한다. 기간 중앙값은 원본 거래로 계산한다.
- Claude와 교차 검토해 수집 상태를 성공·부분·실패·정상 0건으로 분리했다. HTML/오류 XML/총 건수 누락·불일치, 페이지 실패·상한·유효하지 않은 행을 구분한다. 0건을 휴장으로 단정하지 않는다.
- HTTPS만 허용하고 리다이렉트를 차단하며 15초 제한 시간·최대 3회 시도를 적용했다. 동일 요청은 프로세스 내에서 공유하고 자동 수집 재진입을 억제한다. 여러 서버 간 잠금이나 일부 조건이 겹치는 요청의 병합은 구현 범위에 포함되지 않는다.
- DB 고유키 충돌만 중복 처리하고 다른 DB 오류는 실패로 전파한다. 내부 스케줄러와 외부 크론 모두 완전한 수집 확인 후에만 오래된 자료를 정리한다.
- 관심 품목의 혼합 가격 문제는 대표 품종·등급·규격을 고정해 이전 거래와 비교하는 방식으로 보완한다.
- 포장 가격 차트·주간표는 단위 선택 후 표시한다. 단위 목록은 일별 상세를 열기 전에도 선택지 집계에서 제공한다. 전체 규격은 새 비교표에서 분리해서 확인한다.

## 의존성 검토

기존 이미지 빌드에서 취약점 경고를 확인해 npm audit와 공식 공지를 대조했다. Next.js와 NextAuth는 같은 메이저 버전의 보안 수정 버전으로 갱신하고, 설정·코드에서 사용하지 않는 `next-pwa` 의존성을 제거했다. 현재 PWA는 자체 서비스 워커 경로를 사용하므로 이 패키지 제거가 서비스 워커 삭제를 의미하지 않는다.

근거: [Next.js Server Actions 보안 공지](https://github.com/vercel/next.js/security/advisories/GHSA-w37m-7fhw-fmv9), [NextAuth OAuth 검증 보안 공지](https://github.com/nextauthjs/next-auth/security/advisories/GHSA-x445-f3h2-j279). 공지의 취약점 중 일부는 다중 OAuth 제공자 등 조건이 필요하며, 이 앱에서 모두 악용 가능하다고 확인한 것은 아니다.

최종 설치 버전: Next.js/eslint-config-next 16.3.4, NextAuth 4.24.15. Tiptap 계열은 [공식 보안 수정 공지](https://github.com/ueberdosis/tiptap/security/advisories/GHSA-cp6q-959q-f8rh)에 따라 3.31.3으로 맞춰 override했다. 핵심·React 연결·확장 패키지의 peer 버전 불일치를 막기 위한 고정이며 향후 BlockNote 업데이트 시 함께 검토한다. 나머지 의존성은 호환 버전 범위에서 audit fix/update했다. 최종 설치의 npm audit 결과는 알려진 취약점 0건이다. 애플리케이션 전체의 보안 무결성을 보증하는 뜻은 아니다.

새 Turbopack의 동적 파일 추적 경고에 따라 백업·DB 런타임 경로에는 tracing 제외 주석을 추가했다. 사용자 DB/백업을 빌드 자산으로 포함할 필요가 없으며 정적 migration 경로는 추적을 유지한다. 런타임 파일 검증·복원 코드는 바꾸지 않았다.

## 남은 설계 단계

품종·산지 표준코드 사전, 여러 기기 간 프리셋 동기화, 장기 집계 보관, 목표가 알림과 내 작물 연결, 출하 수취액·다시장 비교는 기존 로드맵에 남아 있다. 원천의 수량·등급 의미와 수집 완전성을 검증하고 순서대로 구현한다. 이번 변경으로 해당 기능 전체가 완성됐다고 보지 않는다.

수량 필드가 없는 기존 원천은 1건으로 취급하는 호환 규칙이 남아 있다. 가중 통계는 저장된 수량 기준이며 실제 중량의 정확성을 보장하지 않는다. 실인증 가락 API 호출과 로그인 후 브라우저 전 구간 테스트는 이번 검증에 포함하지 않았다.
