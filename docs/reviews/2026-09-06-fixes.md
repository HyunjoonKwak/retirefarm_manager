# 공동 리뷰 후속 수정 — 2026-09-06

사용자의 수정 진행 승인에 따라 현재 작업 디렉터리에서 Codex/Claude가 범위를 나누어 구현했다. 기존 사용자 세션 설정 파일과 `.omc/` 변경은 작업 범위에 포함하지 않았다. 커밋·푸시·배포·운영 DB 변경은 수행하지 않았다.

## Codex: 인증·백업·운영

- 임의 최초 로그인자 ADMIN 자동 연결/승격과 이메일만으로 연결하는 로직 제거. 운영자가 명시한 `KAKAO_ADMIN_ID`, 기존 ADMIN 연결용 `KAKAO_ADMIN_USER_ID`만 사용한다. 기존 연결 사용자는 그대로 로그인 가능하다.
- JWT의 사용자/권한을 DB에서 갱신한다. 모든 백업 API는 현재 DB의 ADMIN 권한을 확인하고 USER/삭제된 계정을 차단한다. 설정의 백업 탭도 관리자에게만 표시한다.
- SQLite CLI 온라인 백업으로 WAL을 포함한 일관된 snapshot 생성. 실행 중인 DB 파일의 단순 copyFile 백업을 제거했다.
- `.db.gz` 압축 해제, SQLite 헤더/quick_check/foreign_key_check, 앱 테이블과 migration 호환 검증 후 복원을 예약한다. 실행 중인 DB를 API가 덮어쓰지 않는다.
- Docker 부팅 시 연결/마이그레이션 전에 예약 복원을 적용한다. 먼저 최신 안전 백업을 만들고 실패하면 중단한다. 중단된 `.applying` 파일이 남으면 자동 재적용하지 않고 복구를 요구한다. 예약 취소와 재시작 필요 안내를 UI에 반영했다.
- 앱 부팅 시 매분 한국 시간 기준으로 자동 백업 설정 파일을 읽는 실행기 시작. 저장과 실행이 같은 경로/스키마를 사용하며 보관 기간도 적용한다. 안전 백업은 자동 삭제하지 않는다. 앱이 정지된 동안의 스케줄은 소급하지 않는다.
- 불완전·문자열·소수 스케줄 숫자 입력 거부. 경로 조작/심볼릭 링크 파일 거부. 기존 호스트 백업 폴더 환경 변수도 호환한다.
- 주 1회 다음 실행 시간 탐색에서 7일 후를 포함하고 날짜에 의존하던 테스트를 고정 시계로 바꿨다.
- Docker runtime에 sqlite3 도구와 복원 스크립트 포함. 로컬 DB/백업/에이전트 상태를 이미지 빌드 컨텍스트에서 제외. README와 인증 설명을 실제 구성에 맞게 수정했다.

검증(중간): auth/backup/scheduler 대상 33 tests 통과. 일반 USER와 오래된 ADMIN JWT로 8개 백업 핸들러 접근 거부, 관리자 생성 허용, gzip 예약/복원, 안전 백업 실패 시 보존, WAL 연결 유지 중 snapshot, 보관 정책, 한국 시간 스케줄/동일 분 중복 방지 확인. Docker compose 두 구성의 정적 검증 통과. 대상 코드 ESLint 오류·경고 없음.

새 환경 변수, 기존 관리자 연결 절차, 예약 복원과 중단 복구 절차는 README를 따른다. 환경 변수의 실제 관리자 ID는 자동으로 채우지 않았다. 운영 컨테이너/실제 계정에 대한 E2E 검증은 하지 않았다.

## Claude: 금액·자금 계획·날짜 모델

- 필요 자금 계산을 공통 함수로 통일: 수량을 반영한 설립비 순액 + 생활비 버퍼. 자금 요약 화면에서 구성 금액을 설명한다.
- 금액 집계는 Decimal을 사용하여 기존 소수 금액에서도 500 오류가 나지 않게 했다. 신규 금액 입력은 정수 원 단위로 검증한다. 기존 금액은 반올림·정수화하지 않았다.
- 월/연 구간을 [첫날, 다음 기간 첫날)로 통일하여 월말 자금과 거래가 누락되지 않게 했다.
- 설립비에 지출 예정일(plannedDate)·지출일(paidAt)을 추가하고 입력 화면을 연결했다. 과거에 등록했더라도 미지출이면 예측에 배치하며, 날짜 미정·기한 경과·이미 받은 자금에 적용한 가정을 화면에 표시한다.
- 작물 완료일(completedAt)을 상태 전이 시 기록하고 사용자가 교정할 수 있게 했다. 완료 후 메모를 수정해도 재배기간과 완료 월을 바꾸지 않는다.
- 기존 날짜는 일괄 추정하여 DB에 채우지 않는다. 기존 미지출 여부와 완료 날짜는 화면에서 확인·교정할 수 있다.

Claude는 관련 구현과 자체 테스트/보고서 저장 후 세션 사용 한도에 도달하여 완료 신호를 보내지 못했다. 새 Claude 세션은 만들지 않았고, Codex가 구현을 인수해 교차 검토와 전체 검증을 마쳤다. Orca Dispatch는 `abandoned`로 보존하여 Claude가 정상 완료 신호를 보냈다고 기록하지 않았다. 기존 Claude 터미널과 세션은 유지했다.

## Codex 후속 교차 검토

- 레거시 작물의 첫 편집 시 이전 updatedAt을 완료일로 고정하되, 추정 여부가 재조회 때 사라지지 않도록 `completedAtEstimated` 필드를 추가했다. 사용자가 날짜를 명시적으로 교정하면 추정 표시를 해제한다.
- 날짜 미정 설립비에 지정한 영농 시작일이 예측 기간 밖에 있으면 예측 첫 달로 배치하도록 보완했다. 유효하지 않은 영농 시작일은 거부한다.
- 실제 funding/summary 핸들러에서 월말 자금 포함·소수 금액 집계·수량/생활비 버퍼 합산을 검증했다. 실제 crop PATCH 핸들러에서도 첫 편집 → 재편집 → 명시적 완료일 교정의 보존 동작을 검증했다.

## 운영 적용 시 필요한 사항

신규 migration `20260906090000_setup_cost_schedule_crop_completion`은 지출 예정일·지출일·완료일·완료일 추정 여부를 추가한다. **운영 DB에는 아직 적용하지 않았다.** 새 코드를 실행하기 전에 migrate deploy가 필요하며 Docker entrypoint가 이 순서를 수행한다. 배포, 컨테이너 재시작, 실제 계정 로그인/복원 E2E는 이번 작업에서 실행하지 않았다.

기존 설립비는 지출일이 없으므로 이미 지출한 항목의 지출일을 입력해야 미래 유출에서 제외된다. 과거 자금은 현재 보유 현금에 이미 포함됐을 수 있어 자동으로 더하지 않는다. 기존 작물 완료일은 추정 표시를 확인하고 필요하면 교정한다.

저우선순위 후속 항목(subsidyRate 처리 정책, 레거시 은퇴 API 정리, 작물 분석 N+1, 연간 월평균의 정의)과 설계 확인 항목은 원본 리뷰에 남겼다. 이번에는 확인된 주요 권한·백업·금액·날짜 결함을 수정했다.
